함정 모음

  • 서버가 안 떠 있는데 클라이언트가 접속하면 ConnectException: Connection refused(직접 확인).
  • accept()는 클라이언트가 올 때까지 멈춰서 기다려요. JavaFX 화면 스레드에서 부르면 창이 멈춰요 → 별도 스레드에서.

  • 커넥션 풀에서 conn.close()는 진짜로 끊는 게 아니라 풀에 돌려주는 것. 그래도 반드시 불러야 해요(안 부르면 풀이 바닥남).
  • 스레드 풀이 크다고 빠른 게 아니에요. 코어 수는 정해져 있어서 너무 많으면 오히려 느려져요.

🧭 먼저 한국어로 · 👀 읽고 이해하기 (타이핑 안 해도 돼요)

컴퓨터끼리 대화하는 법(TCP, UDP, IP, Port)과, Java 소켓으로 서버와 클라이언트를 만드는 단계를 배워요. 통신 부분은 Week 9 스트림과 똑같아요.

이 챕터 구성

  • 👀 Network: 네트워크 = 컴퓨터를 연결해서 자원 공유(프린터, 파일)와 통신을 하는 것.
  • 👀 Client/Server: 서버: 서비스를 제공하며 기다리는 쪽(웹 서버, DB 서버).
  • 👀 Network Communications and Ports: 컴퓨터에 들어오는 데이터는 랜선/와이파이 하나로 다 들어와요.
  • 👀 TCP: TCP = 전화 통화. 먼저 연결하고(전화 걸기), 말한 순서대로 다 전달되고(신뢰성, 순서 보장), 끝나면 끊어요.

  • 👀 What is Socket?: 서버는 특정 포트(8000)에 ServerSocket을 열고 기다려요.
  • 👀 Client/Server Communications: 서버: new ServerSocket(8000) → server.accept() (기다림) → Socket
  • ⌨️ Server Steps: (⌨️ 8000번 포트에서 반지름(double)을 받아 넓이를 돌려주는 서버를 만들고 실행해 두기)

  • ⌨️ Multi-threaded Server: (⌨️ 서버를 while 루프 + 클라이언트마다 스레드로 바꾸고 클라이언트 두 개를 연달아 실행)

📑 Network #

A network is a system of computers connected together so they can share resources and communicate. An Intranet is a private network (e.g., printers shared in a business). In networking a machine is usually referred to as a host.

🇰🇷 한글 해설

네트워크 = 컴퓨터를 연결해서 자원 공유(프린터, 파일)와 통신을 하는 것. 인트라넷 = 회사 안의 사설 네트워크. 네트워크에 연결된 컴퓨터 한 대를 host라고 불러요.

같은 컴퓨터 안의 프로그램끼리도 네트워크로 대화할 수 있어요. 이때 주소가 localhost(127.0.0.1).

📑 Client/Server #

One (or more) hosts act as servers, and the other hosts are clients that connect to the server. The browser is a client; MySQL Workbench is a client that connects to the MySQL database server. Client and server can be on the same host.

🇰🇷 한글 해설

  • 서버: 서비스를 제공하며 기다리는 쪽(웹 서버, DB 서버).
  • 클라이언트: 서비스를 요청하는 쪽(브라우저, MySQL Workbench, 우리 JavaFX 앱).

Week 8에서 JavaFX 앱이 MySQL에 접속한 것도 클라이언트/서버였어요. 같은 컴퓨터에 둘 다 있어도 구조는 같아요.

📑 Network Communications and Ports #

Computers communicate using a transport protocol: TCP or UDP. A computer usually has one physical connection to the network. How does data get to the targeted application? Answer: Ports. Each application that needs data from the network is assigned a port.

🇰🇷 한글 해설

컴퓨터에 들어오는 데이터는 랜선/와이파이 하나로 다 들어와요. 브라우저, 채팅, 음악 중 누구 것인지 어떻게 알까? → 포트 번호.

비유: IP 주소 = 아파트 주소, 포트 = 호수. 주소로 건물을 찾고 호수로 집(앱)을 찾아요.

📑 TCP #

A connection-based protocol that provides a reliable flow of data between two computers. Like making a telephone call. Used by HTTP, FTP and telnet. The order of data is key. Problems: a connection must be established first, held during the whole communication, closed explicitly, and it holds bandwidth even when idle.

🇰🇷 한글 해설

TCP = 전화 통화. 먼저 연결하고(전화 걸기), 말한 순서대로 다 전달되고(신뢰성, 순서 보장), 끝나면 끊어요.

단점: 연결을 맺는 데 시간이 걸리고, 통화 중엔 말을 안 해도 회선을 잡고 있어요(대역폭 점유), 끝날 때 명시적으로 끊어야 해요.

HTTP, FTP, telnet이 TCP 위에서 돌아요. Java의 Socket, ServerSocket은 TCP예요.

📑 Communication steps TCP #

  1. The client opens a connection to the server. 2. The client sends a request. 3. The server sends a response. 4. The client closes the connection. Steps 2 and 3 may be repeated.

🇰🇷 한글 해설

  1. 클라이언트가 연결 열기 → 2. 요청 보내기 → 3. 서버가 응답 → 4. 클라이언트가 연결 닫기. 2, 3은 여러 번 반복 가능(한 번 연결하고 여러 번 주고받기).

📑 UDP #

A non-connection based protocol that sends independent packets called datagrams, with no guarantee of arrival. Like sending a letter through the postal service: order is not guaranteed and each message is independent. Example: a clock server.

🇰🇷 한글 해설

UDP = 편지(엽서). 연결 없이 패킷(datagram)을 그냥 보내요. 도착 보장 없음, 순서 보장 없음, 하나하나 독립.

빠르고 가벼워서 시간 서버, 영상 스트리밍, 게임처럼 "조금 빠져도 괜찮고 빠른 게 중요한" 곳에 써요. Java에서는 DatagramSocket, DatagramPacket.

TCP UDP
연결 연결형 비연결형
신뢰성 보장 보장 없음
순서 보장 보장 없음
비유 전화 편지

📑 IPv4 and IPv6 #

IPv4: 32-bit addresses (over 4 billion), four integers separated by dots. IPv6: 128-bit addresses, written in hexadecimal separated by colons. The 32-bit IP address identifies the computer; a 16-bit port number identifies the application.

🇰🇷 한글 해설

  • IPv4: 32비트, 192.168.0.10처럼 0~255 숫자 4개를 점으로. 약 43억 개라 부족해짐.
  • IPv6: 128비트, 2001:db8::1처럼 16진수를 콜론으로.

IP는 컴퓨터를, 포트(16비트)는 그 안의 앱을 찾아요.

📑 Port numbers #

Port numbers range from 0 to 65,535. Well-known ports 0 to 1023 are reserved for services such as HTTP and FTP; your applications should not bind to them.

🇰🇷 한글 해설

16비트 → 0 ~ 65535 (2^16 - 1). 0~1023은 well-known(HTTP 80, HTTPS 443, FTP 21 등) 예약이라 우리 앱은 쓰지 말아야 해요. 그래서 예제는 8000번처럼 1024 이상을 써요. 이미 다른 프로그램이 쓰는 포트로 ServerSocket을 만들면 BindException.

📑 Java Networking #

The java.net package has a low-level API (socket programming) and a high-level API (URLs, URIs). We need to know TCP, UDP, IP and ports to make better decisions about which Java classes to use.

🇰🇷 한글 해설

java.net 패키지:

  • 저수준: Socket, ServerSocket, DatagramSocket. 바이트를 직접 주고받기.
  • 고수준: URL, URI, URLConnection. 웹 주소로 자원 가져오기.

프로토콜을 알아야 하는 이유: 믿을 수 있어야 하면 TCP(Socket), 빠른 게 중요하면 UDP(DatagramSocket)처럼 어떤 클래스를 쓸지 고르려고.

📑 Sockets #

A socket is one endpoint of a two-way communication link between two programs running on the network. Socket programming can be connection-oriented (TCP) or connection-less (UDP).

🇰🇷 한글 해설

소켓 = 두 프로그램 사이 양방향 통신선의 한쪽 끝(전화기 한 대). 서버 쪽 소켓과 클라이언트 쪽 소켓이 짝을 이뤄요. 각 소켓에서 읽기(InputStream), 쓰기(OutputStream)를 할 수 있어요.

📑 What is Socket? #

The server has a socket bound to a specific port and waits, listening for a connection request. The client knows the hostname and the port. When the server accepts, it gets a new socket so that it can continue to listen to the original socket for other connection requests.

🇰🇷 한글 해설

  1. 서버는 특정 포트(8000)에 ServerSocket을 열고 기다려요.
  2. 클라이언트는 서버의 호스트 이름과 포트를 알고 접속 요청.
  3. 서버가 받아들이면(accept) 새 Socket을 만들어서 이 클라이언트와 대화해요.

왜 새 소켓? 원래 ServerSocket은 계속 다음 손님을 받는 문 역할을 해야 하니까요. 식당 입구 직원(ServerSocket)이 손님을 자리로 안내하면 담당 웨이터(새 Socket)가 주문을 받는 것과 같아요.

📑 Client/Server Communications #

The server must be running when a client starts. After the server accepts the connection, communication is conducted the same as for I/O streams.

// Server host
ServerSocket server = new ServerSocket(8000);
Socket socket = server.accept();            // waits for a client

// Client host
Socket socket = new Socket(host, 8000);     // request a connection

🇰🇷 한글 해설

그림 요약:

  • 서버: new ServerSocket(8000) → server.accept() (기다림) → Socket
  • 클라이언트: new Socket(host, 8000) → Socket
  • 연결 후: 양쪽 다 Socket의 스트림으로 읽고 쓰기. Week 9 IO와 완전히 같아요.

순서: 서버를 먼저 실행해야 해요.

⚠️ 슬라이드 원본의 SeverSocket, newDataOutputStream은 오타예요(ServerSocket, new DataOutputStream).

📑 Server Steps #

  1. Create a ServerSocket(portNumber, queueLength). 2. Wait for a connection: accept() returns a Socket. 3. Get the socket's I/O streams (getInputStream, getOutputStream), often wrapped in DataInputStream/DataOutputStream or Object streams. 4. Process. 5. Close.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: 8000번 포트에서 반지름(double)을 받아 넓이를 돌려주는 서버를 만들고 실행해 두기

// 예시 코드: 반지름을 받아 원의 넓이를 돌려주는 서버
try (ServerSocket serverSocket = new ServerSocket(8000);
     Socket socket = serverSocket.accept();
     DataInputStream inputFromClient = new DataInputStream(socket.getInputStream());
     DataOutputStream outputToClient = new DataOutputStream(socket.getOutputStream())) {

    double radius = inputFromClient.readDouble();
    outputToClient.writeDouble(radius * radius * Math.PI);
}

🇰🇷 한글 해설

서버 5단계:

  1. new ServerSocket(port, queueLength): 포트 등록. queueLength = 대기 줄 최대 길이.
  2. accept(): 클라이언트가 올 때까지 멈춰서 기다렸다가 Socket 반환.
  3. getInputStream(), getOutputStream(): 보통 DataInputStream/DataOutputStream이나 Object 스트림으로 감싸요(Week 9의 Decorator 감싸기).
  4. 처리: 받고, 계산하고, 보내기.
  5. 닫기: 예시는 try-with-resources라 자동으로 닫혀요.

예시 계산: 반지름 2.0 → 2 × 2 × π = 12.566370614359172 (직접 확인).

📑 Socket and ServerSocket classes #

Socket: getInputStream(), getOutputStream(), close(). ServerSocket: accept() returns the socket and establishes a connection between server and client; close().

🇰🇷 한글 해설

클래스 누가 핵심 메서드
ServerSocket 서버만 accept(), close()
Socket 양쪽 다 getInputStream(), getOutputStream(), close()

클라이언트는 ServerSocket을 쓰지 않아요.

📑 The InetAddress Class #

InetAddress inetAddress = socket.getInetAddress();
System.out.println("Client's host name is " + inetAddress.getHostName());
System.out.println("Client's IP Address is " + inetAddress.getHostAddress());

🇰🇷 한글 해설

서버가 "누가 접속했지?"를 알고 싶을 때. socket.getInetAddress()로 받아서 getHostName()(이름), getHostAddress()(IP 문자열). 같은 컴퓨터에서 테스트하면 127.0.0.1(직접 확인).

InetAddress.getByName("localhost")처럼 이름으로 직접 만들 수도 있어요.

📑 Client Steps #

  1. Create a Socket to connect to the server: new Socket(serverAddress, portNumber). 2. Get the socket's I/O streams. If the server sends with an ObjectOutputStream, the client should read with an ObjectInputStream (same format). 3. Process. 4. Close the streams and the socket; the client must determine when the server is finished sending.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: 서버에 2.0을 보내 Area: 12.566...이 나오는지 확인, 서버를 끄고 다시 실행해 ConnectException도 보기

// 예시 코드: 위 서버에 접속하는 클라이언트
try (Socket socket = new Socket("localhost", 8000);
     DataOutputStream toServer = new DataOutputStream(socket.getOutputStream());
     DataInputStream fromServer = new DataInputStream(socket.getInputStream())) {

    toServer.writeDouble(2.0);
    toServer.flush();
    System.out.println("Area: " + fromServer.readDouble());   // Area: 12.566...
}

🇰🇷 한글 해설

클라이언트 4단계: Socket 만들기 → 스트림 얻기 → 처리 → 닫기.

  • 서버가 보낸 형식 그대로 읽어야 해요. 서버가 writeDouble이면 readDouble, ObjectOutputStream이면 ObjectInputStream.
  • flush(): 버퍼에 남은 데이터를 지금 보내기. 안 하면 서버가 영원히 기다릴 수 있어요.
  • 서버가 없으면 ConnectException: Connection refused.

주의: Object 스트림을 양쪽에서 만들 때, ObjectInputStream 생성자는 상대가 보낸 헤더를 기다려요. 양쪽 다 Input부터 만들면 서로 기다리며 멈출 수 있어서 Output을 먼저 만드는 게 안전해요.

📑 Multi-threaded Server #

Outcomes include the multi-threaded server: the server keeps listening and handles each client in its own thread.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: 서버를 while 루프 + 클라이언트마다 스레드로 바꾸고 클라이언트 두 개를 연달아 실행

// 예시 코드
try (ServerSocket serverSocket = new ServerSocket(8000)) {
    while (true) {
        Socket socket = serverSocket.accept();
        new Thread(() -> handleClient(socket)).start();   // one thread per client
    }
}

🇰🇷 한글 해설

서버 5단계 그대로면 손님 한 명만 받고 끝나요. 실제 서버는:

  1. while (true)로 계속 accept().
  2. 손님마다 새 스레드(Week 11)에서 대화.

그래서 한 손님과 대화 중에도 다른 손님을 받을 수 있어요. 손님이 아주 많으면 스레드를 무한히 만들지 말고 스레드 풀(pool.execute(() -> handleClient(socket)))로. 이게 다음 Segment로 이어져요.

2. 📑 강의 슬라이드: Week 13 · Segment 2. Thread Pooling and JDBC Pooling #

🧭 먼저 한국어로 · 👀 읽고 이해하기 (타이핑 안 해도 돼요)

비싼 자원(스레드, 메모리, DB 연결)을 미리 만들어 두고 재사용하는 풀링 기술을 배워요. 스레드 풀과 JDBC 커넥션 풀이 핵심이에요.

이 챕터 구성

  • 👀 Thread Pools: why?: 효율을 올리는 방법은 스레드 쓰기, 그리고 스레드 풀 쓰기.
  • 👀 Pooling Technology: 풀링 = 미리 준비 + 재사용. 객체 하나 만들 때 Java가 하는 일: 클래스 찾기, 필요하면 로딩, 힙 메모리 찾아서 할당하고 0으로 초기화, 생성자 실행.
  • 👀 Application of Pooling Technology: 풀링 예: 스레드 풀, 메모리 풀, DB 커넥션 풀, HttpClient 커넥션 풀.
  • ⌨️ Thread Pool: (⌨️ 스레드 2개짜리 풀에 작업 5개를 넣고 스레드 이름이 thread-1, thread-2 두 개만 나오는지 확인)
  • 👀 Memory Pool: 큰 메모리 덩어리를 미리 잡아 두고, 요청마다 빈 조각을 "사용 중"으로 표시해서 줘요.
  • 👀 Database Connection Pool: DB 연결(DriverManager.getConnection)은 네트워크 접속, 로그인 확인까지 해서 아주 느려요.
  • 👀 Thread Pool separates threads and tasks: 풀의 핵심 아이디어: 스레드(일꾼)와 작업(할 일)을 분리.
  • 👀 Advantages of Thread Pools: 자원 절약: 스레드마다 스택, 프로그램 카운터 같은 전용 공간이 필요한데, 재사용하니 만들고 없애는 비용이 줄어요.
  • 👀 Disadvantages of Thread Pools: 스레드를 너무 많이 두면 오히려 느려져요. 코어 수는 정해져 있어서 스레드끼리 경쟁하고 전환(context switch)에 시간을 써요.

원문 출처: APD545 Week 13 · Segment 2 "Thread pooling and JDBC Pooling" 강의 슬라이드 (Mahboob Ali, Seneca) 핵심 문장 발췌. 코드는 개념을 보여 주려고 해설용으로 새로 쓴 예시

📑 Thread Pools: why? #

Two ways to improve execution efficiency: use threads, or use thread pools. In production environments, we usually use the latter.

🇰🇷 한글 해설

효율을 올리는 방법은 스레드 쓰기, 그리고 스레드 풀 쓰기. 실제 서비스(production)에서는 거의 항상 풀을 써요. 스레드를 만들고 없애는 비용이 생각보다 크거든요.

📑 Pooling Technology #

Pooling technology refers to preparing some resources in advance, and these pre-prepared resources can be reused when needed. Two main advantages: preparation in advance, and reuse. Creating an object (look up the class, load it, allocate heap memory, run initialization) is complex and time-consuming.

🇰🇷 한글 해설

풀링 = 미리 준비 + 재사용. 객체 하나 만들 때 Java가 하는 일: 클래스 찾기, 필요하면 로딩, 힙 메모리 찾아서 할당하고 0으로 초기화, 생성자 실행. 다 시간이 들어요. 자주 쓰는 비싼 것은 한 번 만들어 두고 돌려 쓰자는 것.

비유: 놀이공원 우산 대여함. 비 올 때마다 우산을 사지 않고 빌려 쓰고 반납.

📑 Application of Pooling Technology #

Thread pool, memory pool, database connection pool, HttpClient connection pool, etc.

🇰🇷 한글 해설

풀링 예: 스레드 풀, 메모리 풀, DB 커넥션 풀, HttpClient 커넥션 풀. 시험에는 "풀링이 쓰이는 곳"으로 이 목록이 나올 수 있어요.

📑 Thread Pool #

A certain number of threads are started in the pool first, all in the sleep state. When a new request comes, a sleeping thread wakes up and processes it; afterwards it sleeps again. If a new thread is created for each client request, the CPU time and memory consumption are staggering.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: 스레드 2개짜리 풀에 작업 5개를 넣고 스레드 이름이 thread-1, thread-2 두 개만 나오는지 확인

// 예시 코드: 스레드 2개로 작업 5개 처리
ExecutorService pool = Executors.newFixedThreadPool(2);
for (int i = 1; i <= 5; i++) {
    int id = i;
    pool.execute(() ->
        System.out.println("task " + id + " on " + Thread.currentThread().getName()));
}
pool.shutdown();
// only pool-1-thread-1 and pool-1-thread-2 appear: threads are reused

🇰🇷 한글 해설

스레드 N개를 미리 띄워 두고 잠자게 해요. 요청이 오면 하나를 깨워서 처리, 끝나면 다시 잠. 요청마다 새로 만들지 않아요.

예: 초당 100개 넘는 요청이 오는 은행 시스템에서 요청마다 스레드를 만들면 CPU와 메모리가 감당 못 해요. 200개짜리 풀이면 그 자원을 실제 업무에 써요.

예시 출력 (직접 확인): 작업은 5개인데 스레드 이름은 pool-1-thread-1, pool-1-thread-2 두 개만 나와요. 같은 스레드가 재사용된 증거예요. (어느 스레드가 어느 작업을 맡을지는 실행마다 달라요.)

📑 Memory Pool #

Enough memory is allocated in advance. Each request gets a free piece, marked as used; releasing it puts it back into the pool, marked idle. Advantages: less memory fragmentation, higher reuse. Disadvantage: wastes memory, since a large idle block is allocated at the beginning and may not be used.

🇰🇷 한글 해설

큰 메모리 덩어리를 미리 잡아 두고, 요청마다 빈 조각을 "사용 중"으로 표시해서 줘요. 다 쓰면 진짜로 해제하지 않고 풀에 "빈 칸"으로 돌려놔요. 앱이 끝날 때 풀 전체를 해제.

장점 단점
메모리 단편화(조각조각 빈 공간) 감소, 재사용 증가 처음에 크게 잡아서 안 쓰는 부분이 낭비

(Java는 GC가 메모리를 관리해서 직접 쓸 일은 적어요. 개념만 알아 두세요.)

📑 Database Connection Pool #

Store database connections as objects in memory when the system is initialized. When the user needs the database, an idle connection is taken from the pool instead of establishing a new one. After use, the connection is put back into the pool (not really closed). Parameters: initial number of connections, upper and lower limits, maximum uses per connection, maximum idle time.

// 예시 코드: 풀에서 빌리고 돌려주는 흐름 (DataSource는 풀 라이브러리가 제공)
try (Connection conn = dataSource.getConnection();          // borrow an idle connection
     PreparedStatement ps = conn.prepareStatement("SELECT name FROM student WHERE id = ?")) {
    ps.setInt(1, 7);
    try (ResultSet rs = ps.executeQuery()) {
        if (rs.next()) System.out.println(rs.getString("name"));
    }
}   // conn.close() returns it to the pool

🇰🇷 한글 해설

DB 연결(DriverManager.getConnection)은 네트워크 접속, 로그인 확인까지 해서 아주 느려요. 그래서:

  1. 프로그램 시작 때 연결 여러 개를 미리 만들어 풀에 둬요.
  2. 필요하면 dataSource.getConnection()으로 놀고 있는 연결을 빌려요.
  3. close()하면 진짜 끊는 게 아니라 풀에 반납.

설정할 수 있는 값: 처음 연결 수, 최소/최대 연결 수, 연결 하나의 최대 사용 횟수, 최대 유휴 시간. 풀이 연결 상태를 감시(monitoring)도 해요.

예시 코드에서 Week 8과 달라진 건 DriverManager 대신 dataSource 한 줄뿐이에요. 그래서 try-with-resources를 그대로 쓰면 자동으로 반납돼요. (실제로는 HikariCP 같은 라이브러리가 DataSource를 만들어 줘요. 이 예시는 DB가 있어야 돌아가서 직접 실행은 안 했어요.)

📑 Thread Pool separates threads and tasks #

A thread pool separates the concepts of threads and tasks, avoiding the performance overhead of frequent creation and destruction. Once a thread is created, it remains in the pool and waits for the next task.

🇰🇷 한글 해설

풀의 핵심 아이디어: **스레드(일꾼)**와 **작업(할 일)**을 분리. 작업은 Runnable로 풀에 넣기만 하고, 어느 일꾼이 할지는 풀이 정해요. 일꾼은 한 번 만들어지면 풀에 남아서 다음 작업을 기다려요.

📑 Advantages of Thread Pools #

  1. Reuse threads to reduce resource consumption (each thread needs its own VM stack, native method stack and program counter). 2. Improve responsiveness: existing threads execute tasks faster. 3. Manage the number of threads and tasks: a fixed number of threads avoids creating threads infinitely.

🇰🇷 한글 해설

  1. 자원 절약: 스레드마다 스택, 프로그램 카운터 같은 전용 공간이 필요한데, 재사용하니 만들고 없애는 비용이 줄어요.
  2. 빠른 응답: 이미 있는 스레드가 바로 일을 시작해요.
  3. 개수 관리: 고정 개수라 스레드가 무한히 늘어나는 걸 막아요.

📑 Disadvantages of Thread Pools #

Too many threads slow the system down: the number of CPU cores is fixed, and too many threads cause contention and frequent thread switching. The appropriate number of threads is key. When tasks exceed a limit, a rejection strategy handles the excess tasks.

🇰🇷 한글 해설

  • 스레드를 너무 많이 두면 오히려 느려져요. 코어 수는 정해져 있어서 스레드끼리 경쟁하고 **전환(context switch)**에 시간을 써요. 적절한 개수가 핵심(보통 코어 수 근처, IO가 많으면 더).
  • 작업이 끝없이 쌓이면 메모리가 부족해져요. 그래서 대기 작업 수에 한도를 두고 넘치면 **거절 정책(rejection policy)**으로 처리해요.
