함정 모음

  • new FileOutputStream("a.dat")는 기존 내용을 지운다. 이어 쓰려면 두 번째 인자 true.
  • close()(또는 flush())를 안 하면 버퍼에 남은 데이터가 파일에 안 써질 수 있다.
  • 파일 열기는 FileNotFoundException, 읽기/쓰기는 IOException. 앞의 것이 뒤의 것의 자식이라 catch 순서는 FileNotFound가 먼저.
  • readObject()는 Object를 반환 → 캐스팅 필요, 그리고 ClassNotFoundException도 처리.
  • 객체 안의 다른 객체 필드도 전부 Serializable이어야 한다. 아니면 NotSerializableException.
  • 슬라이드에 "역직렬화하려면 인자 없는 생성자가 있어야 한다"는 문장이 있는데, 아래 해설처럼 Serializable 클래스 자신은 필요 없다(직접 돌려서 확인).

📑 Files and Streams #

To use a file, it must be first opened. When done with a file, it MUST be closed. The contents of a file is ultimately reduced to a set of numbers from 0 to 255 called bytes. In JAVA, files are represented as Stream objects. The information that is put into a stream comes out in the same order.

🇰🇷 한글 해설

파일은 전원이 꺼져도 남는 저장소예요. 규칙: 열고 → 읽기/쓰기 → 반드시 닫기. 파일의 내용은 결국 0~255 숫자(바이트)의 나열이고, Java에서는 이걸 Stream(흐름) 객체로 다뤄요. 넣은 순서 그대로 나와요(수도관처럼).

📑 Streams #

Streams provide a way to send or receive information to and from files, networks, different programs, and any I/O devices. When a JAVA program starts, 3 streams are automatically created: System.in, System.out, System.err.

JAVA contains four main stream-related hierarchies: InputStream, OutputStream (binary bytes) and Reader, Writer (text). There is no common Stream class; these 4 abstract classes are the roots.

🇰🇷 한글 해설

스트림은 파일만이 아니라 네트워크, 다른 프로그램, 키보드/콘솔에도 똑같이 써요. 그래서 Week 13 소켓도 getInputStream()으로 같은 방식이에요.

4대 뿌리(추상 클래스):

읽기 쓰기
바이트(binary) InputStream OutputStream
문자(text) Reader Writer

이름 끝을 보면 종류를 알 수 있어요: ...Stream은 바이트, ...Reader/Writer는 문자.

📑 Buffers #

I/O is a bottleneck. Buffered output allows data to be collected before it is actually sent; only when the buffer gets full does the data actually get sent. flush() empties the buffer immediately.

System.in is a java.io.BufferedInputStream, System.out is a java.io.PrintStream.

🇰🇷 한글 해설

디스크 접근은 메모리 작업보다 엄청 느려요. 그래서 버퍼(임시 바구니)에 모았다가 한 번에 보내요. 택배를 하나씩 보내지 않고 상자에 모아 보내는 것. flush() = 상자가 안 찼어도 지금 보내기.

System.out이 PrintStream이라는 것도 기억: 우리가 매일 쓰는 println이 사실 스트림이에요.

📑 Writing binary data: FileOutputStream #

new FileOutputStream(String fileName) overwrites an existing file. new FileOutputStream(String fileName, boolean append): if append = true the new data is appended to the end.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: myFile.dat에 HELLO!를 바이트로 쓰고, FileInputStream으로 읽어 숫자 72 69 76 76 79 33이 나오는지 확인

try {
    FileOutputStream out = new FileOutputStream("myFile.dat");
    out.write('H');
    out.write(69);
    out.write(76);
    out.write('L');
    out.write('O');
    out.write('!');
    out.close();
} catch (FileNotFoundException e) {
    System.out.println("Error: Cannot open file for writing");
} catch (IOException e) {
    System.out.println("Error: Cannot write to file");
}

Two exceptions may occur: opening a file may generate FileNotFoundException; reading or writing may generate IOException. In a path string use two backslashes: "F:\\My Documents\\myFile.dat".

🇰🇷 한글 해설

write(int)는 한 바이트(0~255)를 써요. 'H'(문자)도 숫자 72라서 들어가요. 그래서 파일에는 HELLO!가 들어가요(69=E, 76=L).

예외 두 개: 파일을 못 열면 FileNotFoundException, 쓰다가 문제면 IOException. FileNotFound가 IOException의 자식이라 catch는 자식 먼저 써야 해요(반대면 컴파일 에러: unreachable).

윈도우 경로의 \는 문자열에서 특수문자라 \\ 두 번. 맥/리눅스는 /.

📑 DataOutputStream #

A "wrapper" around the FileOutputStream that writes whole primitives and Strings: writeInt, writeDouble, writeBoolean, writeChar, writeUTF(String), ... The output is in binary format.

🇰🇷 한글 해설

int 7293901을 바이트 하나씩 쪼개 쓰는 건 고생이죠. DataOutputStream이 FileOutputStream을 감싸서 writeInt, writeDouble, writeUTF를 제공해요. 이게 데코레이터(wrapper) 패턴이에요(Week 12와 연결).

읽을 때는 DataInputStream으로 쓴 순서 그대로 readInt, readUTF, readDouble. 순서가 틀리면 엉뚱한 값이 나와요. 예: writeInt(7), writeUTF("Hi"), writeDouble(1.5) → 파일 크기 16바이트(int 4 + UTF 길이 2 + 글자 2 + double 8). (직접 돌려 확인했어요.)

📑 Reading binary data: FileInputStream #

FileInputStream in = new FileInputStream("myFile.dat");
while (in.available() > 0)
    System.out.print(in.read() + " ");
in.close();

read() reads a single byte. available() returns the number of bytes available to be read.

🇰🇷 한글 해설

read()는 한 바이트를 int로 돌려주고, 파일 끝이면 -1. available()은 남은 바이트 수. 출력: 72 69 76 76 79 33.

보통은 while ((b = in.read()) != -1) 패턴도 많이 써요.

📑 Writing text: PrintWriter #

When objects are written to the text file, the toString() method is called. PrintWriter behaves just like the System.out console.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: PrintWriter로 이름, 계좌번호, 잔액을 세 줄로 저장하고 BufferedReader로 다시 읽어 출력

PrintWriter out = new PrintWriter(new FileWriter("myAccount2.dat"));
out.println(aBankAccount.getOwner());
out.println(aBankAccount.getAccountNumber());
out.println(aBankAccount.getBalance());
out.close();

🇰🇷 한글 해설

PrintWriter는 파일용 System.out이에요. println(객체)를 하면 그 객체의 toString() 결과가 저장돼요.

new PrintWriter(new FileWriter("x.dat")): FileWriter(문자 단위 파일 쓰기)를 PrintWriter(println 기능)로 감쌈. 텍스트 파일이라 메모장으로 열면 사람이 읽을 수 있어요(바이너리와 차이).

📑 Reading text: BufferedReader and Scanner #

We can only read in characters and lines of text from a text file, but NOT general objects.

BufferedReader in = new BufferedReader(new FileReader("myAccount2.dat"));
String name = in.readLine();
int acc = Integer.parseInt(in.readLine());
float bal = Float.parseFloat(in.readLine());
in.close();

Scanner sc = new Scanner(new FileReader("myAccount2.dat"));
String name2 = sc.nextLine();
int acc2 = sc.nextInt();
float bal2 = sc.nextFloat();
sc.close();

🇰🇷 한글 해설

텍스트로 저장한 건 문자열로만 돌아와요. 숫자는 Integer.parseInt, Float.parseFloat로 다시 바꾸고, 객체는 생성자로 다시 조립해야 해요.

Scanner를 쓰면 nextInt(), nextFloat()로 바로 숫자. 주의: nextInt() 뒤에 nextLine()을 부르면 남은 줄바꿈만 읽어서 빈 문자열이 나오는 유명한 함정이 있어요.

📑 Buffering and Chained Streams #

read()/write() of a single byte is inefficient; each call is handled by the OS. Buffering reads/writes a block of bytes into a memory buffer (byte array, default 8192 bytes). A buffered stream only provides buffering; it works chained with another stream.

BufferedInputStream in = new BufferedInputStream(new FileInputStream("big.dat"));

🇰🇷 한글 해설

read() 한 번 = OS 호출 한 번이라 느려요. Buffered 스트림은 8192바이트씩 미리 읽어 두고 메모리에서 꺼내 줘요.

Chained streams: Buffered는 버퍼링만 하고 파일은 몰라요. 그래서 파일 스트림을 감싸서 써요.

new DataInputStream( new BufferedInputStream( new FileInputStream("a.dat") ) )
   기본형 읽기             버퍼링                 실제 파일

📑 Stream IO Operations #

  1. Open stream 2. Read/Write 3. Close stream

🇰🇷 한글 해설

모든 IO의 3단계: 열기 → 읽기/쓰기 → 닫기. 닫기를 잊으면 파일이 잠기거나(OS 파일 핸들), 쓰기 내용이 버퍼에 남아 사라질 수 있어요.

📑 Standard Template #

FileInputStream in = null;
try {
    in = new FileInputStream(filename);
    // read data
} catch (FileNotFoundException e) {
    // ...
} finally {
    try { if (in != null) in.close(); } catch (IOException e) { }
}

🇰🇷 한글 해설

Java 7 이전 방식: finally에서 닫기. 중간에 예외가 나도 finally는 항상 실행되니까요. in이 null일 수 있어서(열기부터 실패) if (in != null) 검사, close()도 예외를 던질 수 있어서 try-catch가 또 필요해요. 복잡하죠. 그래서 다음 문법이 나왔어요.

참고: 원래 슬라이드는 if(n != null)로 오타가 있어요. in이 맞아요.

📑 try-with-resources (Java 7) #

Works with java.lang.AutoCloseable. The stream is closed automatically.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: 파일 복사 프로그램을 try-with-resources로 쓰기 (입력, 출력 스트림 두 개)

try (FileInputStream in = new FileInputStream(src);
     FileOutputStream out = new FileOutputStream(dst)) {
    // read and write
} catch (FileNotFoundException e) {
    // ...
} catch (IOException e) {
    // ...
}

🇰🇷 한글 해설

try ( 자원 선언 ) { ... }: 블록이 끝나면(예외가 나도) 자동으로 close(). 조건: 자원이 **AutoCloseable**을 구현해야 해요(Week 2의 "Common Interfaces"). 여러 개는 ;로 구분하고, 선언 반대 순서로 닫혀요.

Week 8 JDBC의 Connection, PreparedStatement, ResultSet도 이렇게 닫았죠.

📑 Byte Stream vs Character Stream #

Byte Stream Character Stream
"Raw Data", byte by byte (8 bits) "Character Data", char by char (16 bits)
coder converts bytes to characters no worries for the coder
does not always handle Unicode correctly handles Unicode appropriately

Binary I/O does not involve encoding or decoding and is more efficient than text I/O.

🇰🇷 한글 해설

  • Byte: 1바이트씩, 그림, 소리, .dat 같은 raw 데이터. 글자로 바꾸는 건 내 책임.
  • Character: Java char(2바이트)씩, **Unicode(한글 등)**를 알아서 인코딩.

어느 게 더 효율적? 바이너리(인코딩, 디코딩 과정이 없어서). 시험 단골 질문이에요.

2. 📑 강의 슬라이드: Week 9 · Segment 2. Reading and Writing Whole Objects #

🧭 먼저 한국어로 · 👀 읽고 이해하기 (타이핑 안 해도 돼요)

객체를 필드별로 쪼개지 않고 통째로 저장하는 **직렬화(Serialization)**와, 파일 중간을 바로 읽고 쓰는 RandomAccessFile이에요.

이 챕터 구성

  • 👀 ObjectOutputStream: writeObject(obj) 한 줄로 객체 저장.
  • 👀 Serialization: 직렬화 = 객체를 바이트 줄로 펼치기. 조건: implements Serializable.
  • ⌨️ De-Serialization: (⌨️ BankAccount를 Serializable로 만들어 writeObject로 저장하고 readObject로 다시 읽기 (transient 필드가 null로 돌아오는지도 확인))

📑 ObjectOutputStream #

Save or load entire JAVA objects with one method call, instead of breaking apart the object into its attributes. ObjectOutputStream is a wrapper around the FileOutputStream.

BankAccount aBankAccount = new BankAccount("Rob Banks");
aBankAccount.deposit(100);
ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("myAcc.dat"));
out.writeObject(aBankAccount);
out.close();

🇰🇷 한글 해설

writeObject(obj) 한 줄로 객체 저장. 역시 FileOutputStream을 감싸는 구조예요(객체 → 바이트는 ObjectOutputStream, 바이트 → 파일은 FileOutputStream).

📑 Serialization #

Serialization is the process of breaking down an object into bytes. The object must implement java.io.Serializable. This interface does not have any methods; it acts as a "flag" that indicates your permission for this object to be serialized.

public class BankAccount implements java.io.Serializable { ... }

All of the "pieces" of the object must also be serializable. If BankAccount has a Customer owner, then Customer must be Serializable too. Think of a meat grinder: marbles in the meat cannot come out through the grinder.

🇰🇷 한글 해설

직렬화 = 객체를 바이트 줄로 펼치기. 조건: implements Serializable.

Serializable은 메서드가 하나도 없는 marker interface예요(Week 4 EventListener와 같은 종류). "직렬화해도 된다"는 허락 표시예요. 보안상 아무 객체나 파일이나 네트워크로 나가지 못하게 막는 거죠.

고기 분쇄기 비유: 객체 안에 Serializable이 아닌 필드 객체(구슬)가 있으면 갈 수 없어요 → NotSerializableException. 그래서 Customer owner가 있으면 Customer도 Serializable이어야 해요. String, ArrayList 같은 표준 클래스는 대부분 이미 Serializable.

📑 De-Serialization #

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: BankAccount를 Serializable로 만들어 writeObject로 저장하고 readObject로 다시 읽기 (transient 필드가 null로 돌아오는지도 확인)

try {
    ObjectInputStream in = new ObjectInputStream(new FileInputStream("myAcc.dat"));
    BankAccount aBankAccount = (BankAccount) in.readObject();
    System.out.println(aBankAccount);
    in.close();
} catch (ClassNotFoundException e) {
    System.out.println("Error: Object's class does not match");
} catch (FileNotFoundException e) {
    System.out.println("Error: Cannot open file");
} catch (IOException e) {
    System.out.println("Error: Cannot read from file");
}

Once read in, the object must be type-casted. A ClassNotFoundException may be generated.

🇰🇷 한글 해설

읽기: (BankAccount) in.readObject(). 반환형이 Object라 캐스팅, 그리고 저장된 클래스를 찾지 못하면 ClassNotFoundException(checked라 꼭 처리).

슬라이드에는 "역직렬화하려면 객체에 인자 없는 생성자가 있어야 하고 없으면 IOException"이라는 문장이 있어요. 하지만 같은 강의 뒤쪽 규칙 4번("Constructor of object is never called")과 맞지 않고, 실제로 인자 없는 생성자가 없는 Serializable 클래스도 잘 읽혀요(직접 돌려서 확인, 생성자 출력도 저장할 때 한 번만 찍혀요). 정확한 규칙은: Serializable이 아닌 첫 번째 부모 클래스에 인자 없는 생성자가 있어야 한다(보통 Object라서 신경 쓸 일이 없음). 시험에서 이 문장이 나오면 슬라이드 표현과 실제 규칙이 다르다는 것만 기억해 두세요.

📑 Danger: class changes #

The saved binary format depends on the class name, attribute types and names. If you change the class definition after it has been saved, it may not be able to be read back in again.

🇰🇷 한글 해설

저장된 바이트에는 클래스 이름, 필드 이름과 타입이 들어 있어요. 저장 후 클래스를 고치면(필드 타입 변경, 삭제 등) 옛 파일을 못 읽을 수 있어요(InvalidClassException). 그래서 실무에서는 private static final long serialVersionUID = 1L;을 직접 적어 버전을 관리해요.

📑 transient and custom serialization #

Declare any attribute as transient (it will not be serialized): private transient String password;. You can write writeObject(ObjectOutputStream) and readObject(ObjectInputStream) to override the default; defaultWriteObject() / defaultReadObject() do the default behavior.

private void writeObject(ObjectOutputStream out) throws IOException {
    out.defaultWriteObject();
    out.writeObject(encrypt(password));
}

private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException {
    in.defaultReadObject();
    password = decrypt((String) in.readObject());
}

🇰🇷 한글 해설

transient = "이 필드는 저장하지 마". 비밀번호, 캐시, 소켓처럼 저장하면 안 되거나 못 하는 것. 읽어 오면 기본값(객체는 null, 숫자는 0)이에요.

직접 제어하고 싶으면 클래스 안에 private void writeObject(ObjectOutputStream), private void readObject(ObjectInputStream)를 만들어요. Java가 알아서 불러 줘요(우리가 부르지 않음, Week 7 IoC의 callback). 안에서 defaultWriteObject()로 기본 저장을 먼저 하고, 암호화한 값을 추가로 써요. 슬라이드는 public으로 썼지만 Java 규칙상 private이어야 이렇게 자동 호출돼요.

📑 Serialization rules #

  1. If a parent class has implemented Serializable then child class doesn't need to implement it, but vice-versa is not true.
  2. Only non-static data members are saved.
  3. Static data members and transient data members are not saved.
  4. Constructor of object is never called when an object is de-serialized.
  5. Associated objects must be implementing Serializable.

🇰🇷 한글 해설

다섯 개 규칙(시험용):

  1. 부모가 Serializable이면 자식도 자동으로 Serializable. 반대는 아님. 2~3. static(클래스 공용 값)과 transient는 저장 안 됨. 예: 저장 후 static 값을 9로 바꾸고 읽으면 9가 보여요(파일에서 온 게 아니니까).
  2. 역직렬화 때 생성자 안 불림. 필드는 파일에서 바로 채워져요.
  3. 안에 들어 있는 객체도 Serializable이어야 함.

내가 돌린 예: owner="Rob", balance=100, transient pw="secret", static count → 읽은 결과 Rob 100.0 null 9.

📑 RandomAccessFile #

All streams so far are read-only or write-only, sequential. RandomAccessFile allows a file to be read from and written to at random locations. The file pointer is where the next read or write occurs; readInt() moves it 4 bytes ahead.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: int 5개를 쓰고 seek(8)로 세 번째 int를 읽어 20, 포인터 12, 길이 20인지 확인

RandomAccessFile raf = new RandomAccessFile("test.dat", "rw");   // "r" = read only
for (int k = 0; k < 5; k++) raf.writeInt(k * 10);
raf.seek(8);                         // jump to byte 8 (the 3rd int)
int v = raf.readInt();               // 20
long pos = raf.getFilePointer();     // 12
long len = raf.length();             // 20
raf.close();

🇰🇷 한글 해설

지금까지 스트림은 처음부터 순서대로(sequential)만. 중간 하나를 고치려면 파일을 새로 써야 했어요. RandomAccessFile은 파일 포인터를 원하는 위치로 옮겨(seek) 바로 읽고 써요. 동영상 탐색 바처럼요.

  • 모드: "r" 읽기 전용, "rw" 읽기+쓰기
  • writeInt 5번 → 20바이트. seek(8) → 세 번째 int(0, 10, 20) 위치. readInt() 후 포인터는 12.
  • 고정 크기 레코드(예: int 하나 = 4바이트)라면 n번째 레코드 위치 = n * 레코드크기. 그래서 바로 점프할 수 있어요.

static void save(Map<String, Integer> scores) throws IOException {
    try (PrintWriter out = new PrintWriter(new FileWriter("scores.txt"))) {
        for (Map.Entry<String, Integer> e : scores.entrySet())
            out.println(e.getKey() + "," + e.getValue());
    }
}

static void printAverage() throws IOException {
    try (BufferedReader in = new BufferedReader(new FileReader("scores.txt"))) {
        String line;
        int sum = 0, count = 0;
        while ((line = in.readLine()) != null) {
            String[] parts = line.split(",");
            sum += Integer.parseInt(parts[1].trim());
            count++;
        }
        System.out.println(count == 0 ? 0 : (double) sum / count);
    }
}
