📑 What is Java? #

Java can be broadly defined as

  • A General Purpose: Its not constraint to one particular domain
  • Object Oriented: Helps model real world scenarios in more natural way
  • Platform Independent: Write Once Run Anywhere (WORA)
  • Concurrent: Multithreaded

🇰🇷 한글 해설

Java를 네 단어로 정리한 슬라이드예요. 시험에 그대로 나올 수 있으니 영어 단어 그대로 외워 두세요.

  • General Purpose: 게임, 서버, 데스크톱 앱 등 한 분야에 묶이지 않는 범용 언어.
  • Object Oriented: 클래스와 객체로 현실 세계를 표현.
  • Platform Independent (WORA): 한 번 쓰면(Write Once) 어디서나 실행(Run Anywhere). 비결은 아래에 나오는 JVM.
  • Concurrent: 여러 스레드를 동시에 돌릴 수 있음 (Week 11 Threads에서 자세히).

📑 Why is Java such a Popular Language? #

High quality learning resources · Inbuilt functions and libraries · Active community support · High-quality development tools · Platform Independent · Security

"Java code can run on any underlying platform like Windows, Linux, iOS, or Android without rewriting."

🇰🇷 한글 해설

인기 있는 이유 목록이에요. 외울 필요는 크지 않지만 Platform Independent(Windows, Linux, Android에서 다시 안 고치고 실행)와 Security(네트워크로 받은 코드를 안전한 환경에서 실행) 두 가지는 다른 문제의 근거로도 쓰여요.

📑 How does Java Work? The Platform #

To use Java, a developer needs to understand two things:

  • Java language and APIs: This is the front-end communication between the developer and the Java platform.
  • Java Virtual Machine: This is the back-end communication between the Java platform and the underlying hardware.

🇰🇷 한글 해설

Java를 쓰려면 두 가지를 알아야 한다는 말이에요.

  • Java language와 API: 내가 코드를 쓰는 쪽(front-end). 문법 + 미리 만들어진 라이브러리.
  • JVM: 내 코드와 실제 하드웨어 사이(back-end).

비유하면, 나는 한국어(Java)로 편지를 쓰고, 통역사(JVM)가 각 나라 말(Windows, Mac, Linux 기계어)로 바꿔 주는 구조예요.

📑 Java API #

APIs are important software components bundled with the Java Platform. These are pre-written Java programs that can plug and play existing functionality into your own code.

🇰🇷 한글 해설

API는 "미리 만들어 둔 Java 프로그램 부품"이에요. 날짜 구하기, 수학 계산, 문자열 처리 같은 걸 매번 직접 만들지 않고 가져다 써요. 예: Math.max(3, 7), String.format(...), java.util.Scanner. 우리가 쓰는 코드는 대부분 내가 새로 쓴 코드 + API 코드의 조합이에요.

📑 JVM (Java Virtual Machine) #

The Java Virtual Machine acts as an additional abstraction layer between the Java platform and the underlying machine hardware. Java source code can run only on those machines that have JVM installed on them.

🇰🇷 한글 해설

JVM은 Java 플랫폼과 하드웨어 사이의 추가 추상화 계층이에요. 그래서 "JVM이 설치된 기계에서만 Java가 실행된다"는 말이 나와요. 거꾸로 말하면 JVM만 깔려 있으면 Windows든 Mac이든 같은 .class 파일이 그대로 돌아요. 이게 WORA의 비밀이에요.

📑 Compilers vs Interpreters #

Compilers: the language then compiles (or translates) the entire code into machine code. The compiled code is then run on the hardware.

Interpreters: every high-level code statement is interpreted into machine code on the fly.

🇰🇷 한글 해설

두 방식 비교예요.

  • 컴파일러: 프로그램 전체를 먼저 기계어로 바꾼 다음 실행. (C, C++)
  • 인터프리터: 한 줄씩 그때그때 기계어로 바꿔 실행. (Python 같은 방식)

슬라이드의 Question Time "Is C++ an Interpreted Language?"의 답은 No예요. C++은 컴파일 언어예요.

📑 Java Runtime Environment #

  • The Java program was the first language to combine both methods (compiler & Interpreted) using a Java Virtual Machine (JVM).
  • Any Java file is first compiled into bytecode.
  • Java bytecode can only run in the JVM.
  • The JVM then interprets the bytecode to run it on the underlying hardware platform.

🇰🇷 한글 해설

Java는 위 두 방식을 둘 다 써요. 시험 단골 흐름이니 순서대로 외우세요.

  1. Hello.java를 컴파일해서 Hello.class(bytecode)를 만든다.
  2. bytecode는 JVM 안에서만 실행된다.
  3. JVM이 bytecode를 인터프리트해서 그 OS에 맞게 실행한다.

참고로 슬라이드에 "The Java code compiler is called the Java Virtual Machine"이라는 문장이 있는데, 정확히는 컴파일러는 javac이고 JVM은 실행기예요. 시험에 슬라이드 문장 그대로 나오면 슬라이드 표현을 따르되, 개념은 "javac가 컴파일, JVM이 실행"으로 이해해 두세요.

  • Java Enterprise Edition (JEE): To develop server-side applications

📑 Steps to Use Java SE #

  • Coding: produced by the programmer.
  • Compiling: build the program into bytecode. Result is a ".class" file. Compiler command: javac
  • Running: class file (bytecode) is loaded by the JVM. JVM command: java
  • Bytecode Verification, Internal Integrity Check
  • Execution: Program execution begins from the main entry point.

🇰🇷 한글 해설

실행 단계예요. 명령어 두 개가 핵심이에요.

javac HelloWorld.java   # 컴파일 → HelloWorld.class 생성
java HelloWorld         # JVM이 실행 (.class는 안 붙임)

JVM은 실행 전에 bytecode가 올바른지 검증(Bytecode Verification, Integrity Check)하고, 마지막에 main부터 실행을 시작해요. IntelliJ의 초록 ▶ 버튼이 이 두 명령을 대신 눌러 주는 거예요.

🧭 먼저 한국어로 · 👀 읽고 이해하기 (타이핑 안 해도 돼요)

C++을 배운 사람 입장에서 "Java도 똑같은 것"을 빠르게 훑는 챕터예요. 문법, 반복문, 연산자, OOP 네 기둥, static, for-each, 제네릭. 다른 점만 조심하면 돼요.

이 챕터 구성

  • ⌨️ Syntax and Comments: C++의 int main()이 Java에서는 클래스 안의 public static void main(String[] args)로 바뀌어요. (⌨️ Hello.java를 만들어 main 실행해 보기)
  • 👀 Loops, Conditionals and Operators: for, while, do while, if/else, switch, 산술 연산자, 비교 연산자 모두 C++과 똑같아요.
  • 👀 Basic Data Types: Java 기본 타입 8개와 크기예요. 시험에 크기를 묻는 문제가 나올 수 있어요.
  • 👀 Keywords and Multithreading: break, continue, new, public, private, return, static 같은 키워드는 같은 뜻이에요.
  • 👀 Object Oriented Programming: OOP 네 기둥은 무조건 외우기: Inheritance(상속), Polymorphism(다형성), Abstraction(추상화), Encapsulation(캡슐화).
  • ⌨️ Object Oriented Programming › Inheritance: extends로 부모의 brand와 honk()를 물려받아요. (⌨️ Vehicle/Car 상속 예제 실행해 보기)
  • ⌨️ Object Oriented Programming › Polymorphism: 같은 메서드 호출이 실제 객체에 따라 다르게 동작해요. (⌨️ Animal 타입 변수에 Cat, Dog 넣고 animalSound() 호출해 보기)
  • 👀 Object Oriented Programming › Abstraction: abstract 메서드는 몸통(body)이 없는 메서드예요.
  • 👀 Object Oriented Programming › Encapsulation: 필드는 private로 숨기고, 밖에서는 getter/setter로만 접근하게 하는 것이에요.
  • 👀 Static Keyword: static은 "객체마다 하나"가 아니라 "클래스에 하나"라는 뜻이에요.
  • 👀 ForEach: for (var x : arr)는 "arr의 원소를 하나씩 x에 넣으면서 반복"이에요.
  • 👀 Templates vs Generics: C++의 template에 해당하는 게 Java의 generics예요.

📑 Syntax and Comments #

Every Java Program starts with a class, nothing stays outside the class.

public class Hello {
    /* Every Java Program starts with a class
       nothing stays outside the class */
    public static void main(String[] args) {   // Execution begins from main
        System.out.print("Hello Java");
    }
}

🇰🇷 한글 해설

C++과 거의 같아요. 다른 점은 딱 하나, 모든 코드가 클래스 안에 있어야 한다는 것. C++처럼 클래스 밖에 함수를 둘 수 없어요.

  • public static void main(String[] args): 프로그램 시작점. static이라서 객체를 만들지 않고도 JVM이 바로 부를 수 있어요.
  • System.out.print: 줄바꿈 없음, System.out.println: 줄바꿈 있음. C++의 cout <<에 해당.
  • 주석 //, /* */은 C++과 같아요.

📑 Loops, Conditionals and Operators #

  • All loops such as while, do while, for and so on are all same.
  • All conditional statements such as if, else if, else and switch are all same as well.
  • The arithmetic operators are same in both languages. +, -, /, *
  • The relational operators are also same in both languages. <, >, <=, >=, !=

🇰🇷 한글 해설

📑 Inheritance #

Process by which objects of one class can link and share some common properties of objects from another class.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: Vehicle/Car 상속 예제 실행해 보기

class Vehicle {                       // Base class
    protected String brand = "Ford";
    public void honk() { System.out.println("Tuut, tuut!"); }
}

class Car extends Vehicle {           // Derived class
    private String modelName = "Mustang";

    public static void main(String[] args) {
        Car myCar = new Car();
        myCar.honk();
        System.out.println(myCar.brand + " " + myCar.modelName);
    }
}

🇰🇷 한글 해설

class Car extends Vehicle: Car가 Vehicle의 필드와 메서드를 물려받아요. C++의 class Car : public Vehicle과 같은 뜻.

  • protected String brand: 자식 클래스에서 접근 가능.
  • myCar.honk(): Car에 honk()를 안 썼는데도 부르는 게 돼요. 부모 것이니까요.
  • Java는 클래스 상속이 하나만 돼요(단일 상속). 여러 개를 받고 싶으면 Week 2의 interface를 써요.

📑 Polymorphism #

Allows us to perform a single action in different ways.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: Animal 타입 변수에 Cat, Dog 넣고 animalSound() 호출해 보기

class Animal {
    public void animalSound() { System.out.println("The animal makes a sound"); }
}
class Cat extends Animal {
    public void animalSound() { System.out.println("The cat says: Meo Meo"); }
}
class Dog extends Animal {
    public void animalSound() { System.out.println("The dog says: bow wow"); }
}

class Main {
    public static void main(String[] args) {
        Animal myAnimal = new Animal();
        Animal myCat = new Cat();
        Animal myDog = new Dog();
        myAnimal.animalSound();
        myCat.animalSound();
        myDog.animalSound();
    }
}

🇰🇷 한글 해설

Animal myCat = new Cat(); 이 한 줄이 다형성의 핵심이에요. 변수 타입은 Animal인데 실제 객체는 Cat이에요. myCat.animalSound()를 부르면 실제 객체(Cat)의 메서드가 실행돼서 "The cat says: Meo Meo"가 나와요.

C++에서는 부모 메서드에 virtual을 붙여야 이렇게 동작했죠. Java는 기본이 virtual이라서 아무것도 안 붙여도 돼요. 출력 순서: The animal makes a sound → The cat says: Meo Meo → The dog says: bow wow.

📑 Abstraction #

Includes representing essential features without including the background details.

abstract class Animal {
    public abstract void animalSound();          // Abstract method (does not have a body)
    public void sleep() { System.out.println("Zzz"); }   // Regular method
}
class Cat extends Animal {
    public void animalSound() { System.out.println("The cat says: Meo Meo"); }
}

🇰🇷 한글 해설

abstract 메서드는 몸통(body)이 없는 메서드예요. "동물은 소리를 낸다, 근데 무슨 소리인지는 자식이 정해"라는 뜻이에요.

  • abstract 메서드가 하나라도 있으면 클래스도 abstract class여야 해요.
  • abstract 클래스는 new Animal()로 직접 객체를 만들 수 없어요.
  • 일반 메서드(sleep())는 같이 가질 수 있어요. 이게 Week 2의 interface와 다른 점이에요.

📑 Encapsulation #

Process of combining data and functions into a single unit.

public class Person {
    private String name;
    public String getName() { return name; }              // Getter
    public void setName(String newName) { this.name = newName; }   // Setter
}

🇰🇷 한글 해설

필드는 private로 숨기고, 밖에서는 getter/setter로만 접근하게 하는 것이에요. 왜? setter 안에서 "이름은 빈 문자열 안 됨" 같은 규칙을 지킬 수 있으니까요. 토이 프로젝트 MenuItem.setPrice()에서 음수 가격을 막는 게 바로 이거예요.

📑 Static Keyword #

  • Like C++, static data members in Java are class members and shared among all objects.
  • Static member methods: They can only call other static methods. They must only access static data. They can't access this or super.
  • Static data members and static methods can be accessed without creating an object. They can be accessed using the class names.

🇰🇷 한글 해설

static은 "객체마다 하나"가 아니라 "클래스에 하나"라는 뜻이에요.

class Counter {
    static int count = 0;      // 모든 객체가 공유
    int id;                    // 객체마다 따로
    Counter() { count++; id = count; }
    static void show() {
        System.out.println(count);   // OK: static 데이터
        // System.out.println(id);   // 에러: static 메서드는 인스턴스 필드 못 씀
        // this.id                   // 에러: static 메서드에는 this가 없음
    }
}
// Counter.show();  ← 객체 없이 클래스 이름으로 호출

규칙 세 개(static 메서드는 static만 부르고, static 데이터만 쓰고, this/super를 못 씀)가 시험에 그대로 나와요.

📑 ForEach #

Both use the foreach loop to quickly iterate over the elements of a container (array, vectors, etc.) without performing initialization, testing, or increment/decrement.

int arr[] = { 10, 20, 30, 40 };
for (var x : arr)
    System.out.print(x + " ");

🇰🇷 한글 해설

for (var x : arr)는 "arr의 원소를 하나씩 x에 넣으면서 반복"이에요. 인덱스가 필요 없을 때 써요. var는 타입을 컴파일러가 알아서 추론하는 키워드(여기서는 int). 출력: 10 20 30 40 . Week 3에서 ArrayList를 돌 때도 똑같이 써요.

📑 Templates vs Generics #

Generics in Java and the similar in C++ named Template come in handy, when we want to write a code ... where our program works regardless of the type of data is being passed.

public class GenericClass<T> {
    private T value;
    public GenericClass(T value) { this.value = value; }
    public void showType() {
        System.out.println("Type:" + value.getClass().getSimpleName());
        System.out.println("Value: " + value);
    }
    public static void main(String[] args) {
        GenericClass<String> str = new GenericClass<>("Generics vs Templates");
        GenericClass<Integer> integer = new GenericClass<>(9);
        str.showType();
        integer.showType();
    }
}

🇰🇷 한글 해설

C++의 template에 해당하는 게 Java의 generics예요. GenericClass<T>의 T 자리에 String, Integer 같은 타입을 넣어요. 주의: Java 제네릭에는 int 같은 기본 타입을 못 넣어요. 그래서 Integer(wrapper 클래스)를 써요. 출력은 Type:String, Value: Generics vs Templates, Type:Integer, Value: 9. Week 3 Segment 3에서 자세히 배워요.

  • Java: public class CRectangle { ... } Note: no ";" required here (C++ needs };).

In C++ you write class CRectangle: public CPolygon and call the parent constructor in the initializer list; Java uses extends and super(a,b). In C++ the method must be virtual; in Java methods are overridable by default.

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: Polygon, Rectangle, Triangle, PolyTest 네 파일 만들어 실행하기

// Polygon.java
public class Polygon {
    protected int width, height;
    public Polygon(int a, int b) { width = a; height = b; }
    public int area() { return 0; }
}

// Rectangle.java
public class Rectangle extends Polygon {
    public Rectangle(int a, int b) { super(a, b); }
    public int area() { return width * height; }
}

// Triangle.java
public class Triangle extends Polygon {
    public Triangle(int a, int b) { super(a, b); }
    public int area() { return width * height / 2; }
}

// PolyTest.java
public class PolyTest {

}

C++ ↔ Java 대응표예요.

C++ Java
class CRectangle: public CPolygon class Rectangle extends Polygon
CRectangle(int a,int b): CPolygon(a,b) {} public Rectangle(int a,int b) { super(a,b); }
virtual int area() 그냥 public int area() (기본이 virtual)

  • Static Block: Unlike C++, Java supports a special block, called static block (also called static clause) which can be used for static initialization of a class. This code inside the static block is executed only once.
  • Static Local Variable: Unlike Java, C++ supports static local variables.

🇰🇷 한글 해설

  • static 지역 변수: C++에만 있음. Java에서는 메서드 안에 static int x;를 쓰면 컴파일 에러예요. 함수 호출 사이에 값을 유지하고 싶으면 static 필드를 써야 해요.

📑 What is Design Pattern? #

  • Designing object-oriented software is hard and designing reusable object-oriented software is even harder.
  • Design patterns make it easier to reuse successful designs and architectures.
  • The design patterns are descriptions of communicating objects and classes that are customized to solve a general design problem in a particular context.

🇰🇷 한글 해설

디자인 패턴은 "자주 나오는 설계 문제에 대한 검증된 해결 방법"이에요. 연결 리스트 같은 자료구조 코드도 아니고, 앱 전체 설계도도 아니에요. "어떤 클래스들이 어떤 역할로 서로 대화하는지"를 설명한 것이에요.

슬라이드 Question Time "Why we need Design Pattern?"의 정답은 Can accelerate development process(개발을 빠르게 해 줌)예요. "GC를 관리한다", "그냥 재미로"는 오답.

📑 What is MVC? #

MVC is a software design pattern. It describes the separation of software into three elements: Model, View, Controller

🇰🇷 한글 해설

MVC = 앱을 세 덩어리로 나누는 디자인 패턴. 카페로 비유하면:

  • Model = 창고와 가격표 (데이터와 규칙)
  • View = 메뉴판과 카운터 화면 (보여주기)
  • Controller = 직원 (주문 받고, 창고 확인하고, 화면에 알려줌)

📑 What is Model in MVC? #

  • Manages the data of an application.
  • The model is agnostic to the way the data is represented to the user or any application workflow, so it can be said that the model is the central part of a MVC application.
  • Developing a model is among the first steps of any MVC software project.
// class that represents model
public class Employee {
    private String EmployeeName;
    private String EmployeeId;

    public String getId() { return EmployeeId; }
    public void setId(String id) { this.EmployeeId = id; }
    public String getName() { return EmployeeName; }
    public void setName(String name) { this.EmployeeName = name; }
}

🇰🇷 한글 해설

Model은 앱의 데이터를 관리해요. 가장 중요한 단어는 agnostic: Model은 데이터가 화면에 어떻게 보이는지 전혀 몰라요. 그래서 Model 안에 System.out.println이나 버튼 코드가 있으면 안 돼요.

Employee 클래스는 private 필드 + getter/setter만 있는 전형적인 Model이에요. 그리고 "Model 만들기가 MVC 프로젝트의 첫 단계"라는 문장도 기억하세요. Week 5에서도 Model을 먼저 만들고 테스트한 다음 View를 만들어요.

📑 Why use MVC Design Pattern? #

This makes it easier to work on each part separately, so you can update or fix things without messing up the whole app. It helps developers add new features smoothly, makes testing simpler, and allows for better user interfaces.

🇰🇷 한글 해설

장점: 각 부분을 따로 고칠 수 있고(앱 전체를 망가뜨리지 않음), 새 기능 추가가 쉽고, 테스트가 쉬워지고, 더 좋은 UI를 만들 수 있어요. 예를 들어 Week 4에서 콘솔 View를 JavaFX 화면으로 바꿔도 Model은 그대로예요.

📑 What is View in MVC? #

  • Describes the presentation of the data and control elements (inputs, buttons, check boxes, menus, and so on) to the user.
  • A view also may use different technologies, like a GUI component installed on the user's PC, an app on a mobile phone, or a web page to be viewed in a browser.
// class which represents the view
public class EmployeeView {
    public void printEmployeeDetails(String EmployeeName, String EmployeeId) {
        System.out.println("Employee Details: ");
        System.out.println("Name: " + EmployeeName);
        System.out.println("Employee ID: " + EmployeeId);
    }
}

🇰🇷 한글 해설

View는 데이터와 입력 요소(버튼, 체크박스, 메뉴 등)를 사용자에게 보여주는 부분이에요. 같은 Model을 여러 View로 보여줄 수 있어요: PC 프로그램, 모바일 앱, 웹페이지. EmployeeView는 값을 받아서 출력만 해요. 계산도 없고 Employee 객체를 직접 바꾸지도 않아요.

📑 What is Controller in MVC? #

  • Handles user input and prepares the data set necessary for the view part to do its work.
  • While a view shows model items, the view never has to know how data is stored and retrieved from some persistent storage (database).
  • Because the user input determines what an application has to do next, the controller also contains the application logic.
  • Any calculation and data transformation happens in the control part of MVC.
// class which represent the controller
public class EmployeeController {
    private Employee model;
    private EmployeeView view;

    public EmployeeController(Employee model, EmployeeView view) {
        this.model = model;
        this.view = view;
    }

    public void setEmployeeName(String name) { model.setName(name); }
    public void setEmployeeId(String id) { model.setId(id); }
    public String getEmployeeId() { return model.getId(); }

    // method to update view
    public void updateView() {
        view.printEmployeeDetails(model.getName(), model.getId());
    }
}

🇰🇷 한글 해설

Controller 문장 네 개가 시험 단골이에요.

  1. 사용자 입력을 처리하고 View에 필요한 데이터를 준비한다.
  2. View는 데이터가 어떻게 저장되고 가져와지는지(DB 등) 절대 알 필요가 없다.
  3. 사용자 입력이 다음에 할 일을 정하니까, Controller가 application logic을 가진다.
  4. 모든 계산과 데이터 변환은 Controller에서 한다.

EmployeeController는 생성자로 model과 view를 둘 다 받아서 들고 있어요. M과 V를 둘 다 아는 건 Controller뿐이에요. updateView()는 Model에서 값을 꺼내 View에 넘겨줘요.

(Week 3에서 "계산은 Service Layer로 옮긴다"는 내용이 나오는데, Week 1 슬라이드 기준 답은 Controller예요.)

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: Employee, EmployeeView, EmployeeController, MVCMain 네 클래스를 만들어 실행하기

public class MVCMain {
    public static void main(String[] args) {
        // fetching the employee record based on the employee_id from the database
        Employee model = retriveEmployeeFromDatabase();
        // creating a view to write Employee details on console
        EmployeeView view = new EmployeeView();
        EmployeeController controller = new EmployeeController(model, view);
        controller.updateView();

        // updating the model data
        controller.setEmployeeName("Frank");

        Employee employee = new Employee();
        employee.setName("Joe");
        employee.setId("11");
        return employee;

}

  1. Model 준비 (DB에서 가져왔다고 가정)
  2. View 생성
  3. Controller에 둘 다 넘김 → updateView()로 출력

📑 MVC in Java, in one sentence each #

  • a model (stored in memory) defines the application's state;
  • a view shows model values and sends user interactions to a controller;
  • the controller prepares model data, handles user input and accordingly changes model values, and then decides which view page to show next.

🇰🇷 한글 해설

마지막 정리 슬라이드예요. 한 줄씩 외워 두세요.

  • model: 메모리에 있는 앱의 상태(state).
  • view: model 값을 보여주고, 사용자 동작을 controller에게 전달.
  • controller: model 데이터를 준비하고, 입력을 처리해 model 값을 바꾸고, 다음에 보여줄 view를 결정.

5. 📑 강의 슬라이드: Week 1 · Java Code Conventions #

🧭 먼저 한국어로 · ⏭️ 가볍게 훑기

Java 코드 작성 규칙 문서예요. 전부 외울 필요는 없고 이름 규칙 표만 확실히 알면 돼요. 과제 채점에서도 이름 규칙을 봐요.

이 챕터 구성

  • 👀 Why Have Code Conventions: 소프트웨어 비용의 80%가 유지보수이고, 대부분 원래 작성자가 아닌 사람이 유지보수해요.
  • 👀 File Names and Organization: 파일 하나에 public 클래스(또는 인터페이스) 하나, 그리고 파일 이름 = public 클래스 이름 (Employee.java 안에 public class Employee).
  • 👀 Order inside a Class: 클래스 안 순서: static 변수 → 인스턴스 변수 → 생성자 → 메서드.
  • 👀 Indentation and Line Length: 들여쓰기 4칸, 한 줄 80자 이내, 줄을 나눌 때는 쉼표 뒤, 연산자 앞에서 끊어요.
  • 👀 Naming Conventions: 변수 이름을 _나 $로 시작하지 않기. i, j, k 같은 한 글자는 반복문 임시 변수에만.

📑 Why Have Code Conventions #

  • 80% of the lifetime cost of a piece of software goes to maintenance.
  • Hardly any software is maintained for its whole life by the original author.
  • Code conventions improve the readability of the software, allowing engineers to understand new code more quickly and thoroughly.

🇰🇷 한글 해설

소프트웨어 비용의 80%가 유지보수이고, 대부분 원래 작성자가 아닌 사람이 유지보수해요. 그래서 모두 같은 규칙으로 써야 남이 빨리 읽을 수 있어요.

📑 File Names and Organization #

  • Java source .java, Java bytecode .class
  • Files longer than 2000 lines are cumbersome and should be avoided.
  • Each Java source file contains a single public class or interface.
  • Order: Beginning comments, Package and Import statements, Class and interface declarations.

🇰🇷 한글 해설

  • 파일 하나에 public 클래스(또는 인터페이스) 하나, 그리고 파일 이름 = public 클래스 이름 (Employee.java 안에 public class Employee). 이건 규칙이 아니라 컴파일러가 강제해요.
  • 파일 순서: 맨 위 주석 → package → import → 클래스.
  • 2000줄 넘는 파일은 피하기.

📑 Order inside a Class #

  1. Class (static) variables: public, then protected, then package level, then private
  2. Instance variables: same order
  3. Constructors
  4. Methods: grouped by functionality rather than by scope or accessibility

🇰🇷 한글 해설

클래스 안 순서: static 변수 → 인스턴스 변수 → 생성자 → 메서드. 변수는 public → protected → (package) → private 순서. 메서드는 접근 제어자가 아니라 기능별로 묶어요. Workshop 코드도 이 순서로 쓰면 깔끔해 보여요.

📑 Indentation and Line Length #

  • Four spaces should be used as the unit of indentation.
  • Avoid lines longer than 80 characters.
  • Break after a comma. Break before an operator.

🇰🇷 한글 해설

들여쓰기 4칸, 한 줄 80자 이내, 줄을 나눌 때는 쉼표 뒤, 연산자 앞에서 끊어요. IntelliJ에서 Cmd + Option + L(Mac) 하면 자동 정렬돼요.

💻 Example: Abstract base class Person #

⌨️ 이 코드는 IntelliJ에서 직접 쳐 보세요: Person, Staff, Student, Teacher를 패키지 나눠서 만들기

package ca.senecacollege.abstracts;

public abstract class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }

    public void greet() {
        System.out.println("Hello, my name is " + name);
    }

    public abstract String getDetails();
}

🇰🇷 한글 해설

Person은 abstract 클래스예요. 공통 필드(name, age), getter/setter, 공통 메서드 greet()는 여기 두고, 사람마다 다른 getDetails()는 abstract로 남겨서 자식이 꼭 만들게 해요. new Person(...)은 안 되지만 Person p = new Student(...)는 돼요.

💻 Example: Staff, Student, Teacher (models) #

public abstract class Staff extends Person {
    private String department;

    public Staff(String name, int age, String department) {
        super(name, age);
        this.department = department;
    }
    public String getDepartment() { return department; }

    @Override
    public String getDetails() {
        return "Department Name: " + getDepartment();
    }
}

public class Student extends Person {
    private String studentID;

    public Student(String name, int age, String studentID) {
        super(name, age);
        this.studentID = studentID;
    }

    @Override
    public String getDetails() {
        return "Student ID: " + studentID;
    }
}

public class Teacher extends Staff {
    private String subject;

    public Teacher(String name, int age, String department, String subject) {
        super(name, age, department);
        this.subject = subject;
    }

    @Override
    public String getDetails() {
        return super.getDetails() + ",  Subject: " + subject;
    }
    public String getSubject() { return subject; }
}

🇰🇷 한글 해설

상속이 두 단계예요: Person ← Staff ← Teacher, 그리고 Person ← Student.

  • 모든 자식 생성자의 첫 줄이 super(...)예요. 부모 필드는 private이라 자식이 직접 못 넣고 부모 생성자에게 맡겨요.
  • Staff도 abstract예요. 그래서 getDetails()를 구현했지만 new Staff(...)는 못 해요.
  • Teacher.getDetails()의 super.getDetails() + ", Subject: " + subject: 부모 결과("Department Name: Mathematics")에 덧붙이는 오버라이드 패턴이에요.
  • @Override는 "부모 메서드를 덮어쓴다"는 표시. 철자를 틀리면 컴파일러가 잡아 줘요. 꼭 붙이는 습관을 들이세요.

추상 메서드가 딱 하나인 인터페이스를 functional interface라고 해요. @FunctionalInterface를 붙이면 컴파일러가 "하나만 있는지" 검사해 줘요. 이런 인터페이스는 람다로 구현할 수 있어요 (아래 TestMain). 람다는 Week 10에서 본격적으로 배우지만, 교수님이 Week 1부터 맛보기로 보여 줬어요.

💻 Example: View and Controller #

public class SchoolView {
    public void displayPersonDetails(String personType, String name, int age, String details) {
        System.out.println("Details of the " + personType + ":");
        System.out.println("Name: " + name);
        System.out.println("Age: " + age);
        System.out.println(details);
        System.out.println();
    }

    public void displayRole(String message) {
        System.out.println(message);
    }
}

public class SchoolController {
    private SchoolView view;

    public SchoolController(SchoolView view) {
        this.view = view;
    }

    public void displayPersonDetails(Person person) {
        view.displayPersonDetails(person.getClass().getSimpleName(),
                                  person.getName(),
                                  person.getAge(),
                                  person.getDetails());
    }

    public void performPersonRole(Person p, IPersonAction action) {
        String message = action.performRole(p);
        view.displayRole(message);
    }
}

🇰🇷 한글 해설

SchoolView는 받은 문자열과 숫자를 출력만 해요. SchoolController는 Model(Person)에서 값을 꺼내 View에 넘겨줘요. 슬라이드의 EmployeeView/EmployeeController와 똑같은 구조예요.

  • person.getClass().getSimpleName(): 실제 객체의 클래스 이름("Student", "Teacher")을 문자열로 줘요. 변수 타입이 Person이어도 실제 객체 이름이 나와요 (다형성).
  • person.getDetails(): 실제 객체의 오버라이드된 메서드가 불려요.
  • performPersonRole(Person p, IPersonAction action): "무엇을 할지"를 매개변수로 받아요. 행동을 값처럼 넘기는 거예요.

public class TestMain {
    static void main() {
        SchoolView view = new SchoolView();
        SchoolController sc = new SchoolController(view);   // controller

        Student student = new Student("Alice", 21, "S1234");          // model
        Teacher teacher = new Teacher("Bob", 32, "Mathematics", "Calculus - 1");

        sc.displayPersonDetails(student);
        sc.displayPersonDetails(teacher);

        // Lambda for roles
        IPersonAction studentRole = (person) -> person.getName() + " is studying";
        IPersonAction teacherRole = (person) -> {
            Teacher t = (Teacher) person;
            return t.getName() + " is teaching" + t.getSubject();
        };

        sc.performPersonRole(student, studentRole);
        sc.performPersonRole(teacher, teacherRole);
    }
}
